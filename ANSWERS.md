# Ответы на вопросы

Микрогейт ИИ: React + Node.js + PostgreSQL. Минимальный работающий код, без лишних слоёв.

## Что сделано

1. Анонимный вход: при первом запросе сервер ставит HttpOnly cookie `sid` (UUID). Логина нет.
2. Форма запроса на клиенте. `POST /api/chat` стримит ответ (SSE).
3. Любой ИИ-гейт: прокси на OpenAI-совместимый `/v1/chat/completions`. Меняются только `AI_BASE_URL`, `AI_API_KEY`, `AI_MODEL`.
4. История сессии:
   - **cookie** — идентификатор сессии;
   - **localStorage** — мгновенная копия переписки в браузере;
   - **PostgreSQL** — источник правды, таблица `messages` по `session_id`.

Без ключа приложение отвечает mock-стримом, чтобы можно было проверить весь путь.

## Архитектура

```
браузер  →  Vite :5173 (proxy /api)
                ↓
            Express :3001
                ├─ cookie sid
                ├─ SSE-стрим
                ├─ Postgres :5433
                └─ внешний LLM-гейт
```

Клиент не ходит в OpenAI напрямую: ключ живёт только на сервере.

| Слой | Роль |
|---|---|
| React | форма, стрим токенов, запись в localStorage |
| Express | сессия, история, прокси к модели |
| Postgres | сообщения `{session_id, role, content}` |

На машине без WSL Docker-движок не стартует — Postgres поднимается embedded (`data/pg`). `docker-compose.yml` оставлен для стенда, где Docker уже есть.

## Структура

```
server.js           API, cookie, SSE, Postgres
src/App.jsx         форма, стрим, localStorage
src/styles.css      минимальный UI
vite.config.js      dev-сервер + proxy /api → :3001
docker-compose.yml  опциональный Postgres
.env.example        URL / ключ / модель гейта
ANSWERS.md          этот файл
```

Нет ORM, auth-библиотеки, UI-кита, Redux. Один POST, одна таблица, один cookie.

## API

- `GET /api/session` — выдать/создать `sid`
- `GET /api/history` — сообщения текущей сессии
- `POST /api/chat` `{ message }` — сохранить user-сообщение, стримить ответ, сохранить assistant

## Как не делать нейрослоп

Не генерировать «платформу» на пустом задании. Не тащить markdown-рендер, градиенты, «Ask me anything» и `ChatServiceFactory`. Стрим — это `data: {delta}` по SSE, не WebSocket «на будущее». История пишется дважды сознательно: localStorage для UX, Postgres для правды. Провайдер — URL+ключ, не вендорский SDK, иначе гейт сразу привязан к одному API.

## Что ещё можно добавить в такой сервис

1. Маршрутизация моделей: дешёвая для черновика, дорогая для финала, локальная для секретов.
2. Бюджет и лимиты на сессию/день (токены, деньги, slow-mode).
3. Bring-your-own-key: ключ только на сервере, не в localStorage.
4. Плейсменты: чат, саммари, извлечение полей, перевод — один гейт, разные системные промпты.
5. Инструменты: поиск, браузер, SQL read-only, файлы.
6. Команды, шаринг треда по ссылке, экспорт в Markdown.
7. Оценка качества: thumbs, регресс-набор промптов, сравнение двух моделей.
8. Политики: PII-redaction, запрет выноса промпта, audit log для B2B.
9. Кэш семантически одинаковых запросов.
10. White-label: домен, модель, системный промпт под вертикаль.
11. Голос и картинки в той же сессии.
12. A/B системных промптов без деплоя.
13. Webhook: ответ гейта → CRM / Telegram / тикет.
14. Offline-очередь в IndexedDB.
15. Коннекторы к внутренним API компании.

Смысл продукта не в «доступе к модели», а в контролируемом входе: кто спросил, сколько стоило, куда ушло, можно ли повторить.
